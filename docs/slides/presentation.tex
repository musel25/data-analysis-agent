\section{1 · The problem}
% ===========================================================================

\begin{frame}{The assignment, stated plainly}
\why{Part 2, Option A. Before any design, be precise about what the thing must do.}

\begin{block}{The system under construction}
Give an agent \textbf{a question in English} and \textbf{a folder of data files}. It must:
\begin{enumerate}
  \item \textbf{explore} the data (it has never seen it),
  \item \textbf{choose} an analytical approach,
  \item \textbf{write and run code},
  \item \textbf{check its own intermediate results},
  \item return a \textbf{structured, defensible answer}.
\end{enumerate}
\end{block}
\pause
\begin{itemize}
  \item It is \emph{not} a chatbot, and \emph{not} a literature-search agent.
  \item It is exactly the system \textbf{both supplied papers evaluate} — which is why the papers
        are not background reading. They are \textbf{failure data for the thing I am about to
        build}.
\end{itemize}
\end{frame}

\why{Phase-II clinical trial, 800 patients, four undocumented landmines in the file.}

\begin{frame}{Simpson's paradox — the whole talk in one mechanism}
\why{If you take one idea from the first section, take this one.}

\begin{enumerate}
  \item The trial was \textbf{not randomised}. Clinicians gave the drug to the patients who were
        \textbf{already sicker}.\pause
  \item So the treatment arm is \textbf{loaded with severe cases}, and severe cases respond worse
        \emph{whatever} you give them.\pause
  \item The pooled comparison is therefore \textbf{not} comparing treatment vs.\ control.
        \\ It is comparing \textbf{sick people vs.\ healthy people}.\pause
  \item Every number the agent printed was \textbf{arithmetically correct}. The code was clean.
        The conclusion was \textbf{backwards}.
\end{enumerate}

\pause
\begin{block}{The lesson that sets up everything else}
The failure is \textbf{not} in the code. It is in the \textbf{seam between what the data showed
and what the agent decided}. \\[3pt]
You cannot fix that with a better programmer. You fix it with \textbf{structure}.
\end{block}
\end{frame}

\section{2 · What an agent actually is}
% ===========================================================================

\begin{frame}{Step 0 — a language model cannot do anything}
\why{Beginners skip this and then mis-attribute every later design choice. Ten seconds, no shortcuts.}

\begin{block}{An LLM is a pure function}
\[
\texttt{text in} \;\longrightarrow\; \texttt{text out}
\]
It cannot read a file. It cannot run Python. It cannot see your dataframe.
\end{block}

\pause
So if you ask it \emph{``what is the mean flipper length in \code{penguins.csv}?''} it will
\textbf{invent a plausible number}. Not because it is lying — because \textbf{inventing plausible
text is the only operation it has}.

\pause
\medskip
\begin{alertblock}{The founding rule of this entire design}
\textbf{Never ask the model for a number. Ask it for \emph{code that computes} the number.}\\
The model is a \textbf{bad calculator} and a \textbf{very good programmer}. Use it as the
programmer.
\end{alertblock}
\end{frame}

\begin{frame}{Step 1 — tool calling: who actually runs the code?}
\why{The question you asked me, and the one the papers never spell out. The answer is: not the model.}

\begin{enumerate}
  \item \textbf{You} describe a tool to the model as a JSON schema:
        \code{run\_python(code: str)}.\pause
  \item The model \textbf{does not run it}. It emits a \textbf{text request}:
        \\[3pt]
        \code{\{"tool": "run\_python", "code": "print(df.mean())"\}}\pause
  \item \textbf{Your Python program} parses that request, executes the code
        \textbf{in a process you control}, and captures \code{stdout}.\pause
  \item You paste the output back into the conversation as a new message.
        The model reads it on the next turn.
\end{enumerate}

\pause
\begin{block}{So ``giving a model tools'' is not a model capability}
It is \textbf{a loop that you write}. The model only ever produces text; the \emph{harness} gives
that text consequences.\\[3pt]
\textbf{Both papers do exactly this} — the difference is only \emph{where} step 3 runs
(a Docker container, for them).
\end{block}
\end{frame}

\begin{frame}[fragile]{Step 2 — the ReAct loop, in full}
\why{Yao et al., 2022. This is the entire ``agent''. It is about 40 lines.}

\begin{columns}[T]
\begin{column}{0.52\textwidth}
\begin{lstlisting}[emph={gates}]
# messages = the agent's whole memory
messages = [system, briefing, question]

for step in range(MAX_STEPS):

    reply = llm(messages, tools)   # 1 THINK

    if reply.tool == "submit_answer":
        ok, why = gates(reply)     # 4 GATE
        if ok:
            return reply.report    #   DONE
        obs = why                  #   rejected

    else:
        obs = execute(reply.tool)  # 2 ACT

    messages.append(reply)         # 3 OBSERVE
    messages.append(obs)
\end{lstlisting}
\end{column}
\pause
\begin{column}{0.44\textwidth}
\textbf{Three moving parts, that is all:}
\medskip
\begin{itemize}
  \item \textbf{THINK} — one API call. The model picks a tool.
  \item \textbf{ACT} — \emph{your} code executes it.
  \item \textbf{OBSERVE} — the result is appended, so the \emph{next} call sees it.
\end{itemize}
\medskip
\pause
\begin{alertblock}{Where the design lives}
The loop is \textbf{unremarkable}, and that is the point.\\
\textbf{All the engineering is in \gd{gates()} and in what goes into \gd{messages}.}
\end{alertblock}
\end{column}
\end{columns}
\end{frame}

\begin{frame}{Step 3 — exactly three tools, and why not more}
\why{Every extra tool is surface area for the model to misuse. The papers show it is not failing for lack of affordances.}

\begin{block}{\code{run\_python(code)} — the only capability it needs}
Executes in a \textbf{persistent namespace}, like Jupyter cells. Variables survive across steps.
Returns \code{stdout} + truncated traceback.\\[3pt]
\sm{\textbf{Why one general tool, not many:} \code{value\_counts}, \code{groupby},
\code{correlate} as separate tools would cap the agent at \textbf{whatever verbs I anticipated}.
Anything pandas can do, the agent can do.}
\end{block}
\pause
\begin{block}{\code{note\_finding(observation, implication, status)} — the ledger}
It must \emph{write down} anything it notices. \sm{\textbf{§4.}}
\end{block}
\pause
\begin{block}{\code{submit\_answer(report)} — \alert{a gated action, not a default}}
Finishing is something the agent must \textbf{earn}. \sm{\textbf{§4.}}
\end{block}
\end{frame}

\begin{frame}[shrink=8]{Step 4 — what the model sees, and what it never sees}
\why{The single most important context rule, and the one that makes the design scale-invariant.}

\begin{alertblock}{The model never sees the data}
It sees \textbf{metadata}, \textbf{summaries}, and \textbf{the output of code it wrote itself}.
\end{alertblock}

\pause
\begin{itemize}
  \item A 200{,}000-row dataframe and a 200-row one cost \textbf{the same number of tokens} —
        because in both cases the model is looking at \code{df.dtypes}, \code{df.head(3)}, and
        whatever it chose to \code{print}.
  \item The dataframe lives \textbf{in the executor process}. Nothing in the loop or the prompts
        changes if the CSV becomes a 10\,GB parquet. \textbf{Only the code the agent writes
        changes.}
\end{itemize}

\pause
\medskip
Four mechanisms keep the context honest:
\medskip

{\footnotesize
\begin{tabular}{@{}p{0.26\textwidth}p{0.66\textwidth}@{}}
\toprule
\textbf{data briefing} & Plain Python computes shape, dtypes, \code{head(3)}, nulls, cardinality \textbf{before the model is called once}. It never starts blind. \\
\textbf{head+tail truncation} & $\sim$1{,}500 chars. \textbf{Tail is kept because Python puts the exception on the \emph{last} line} — head-only truncation throws away the only part of a traceback that matters. \\
\textbf{state banner} & \code{df: DataFrame(1200x9) | clean: DataFrame(1043x9)} — \textbf{recomputed from the live namespace every turn}, so the agent cannot reason about variables that no longer exist. \\
\textbf{matplotlib guard} & \emph{``2 figures saved; you cannot see images — print the numbers you need.''} Kills plot-instead-of-compute. \\
\bottomrule
\end{tabular}}
\end{frame}

\end{itemize}

\begin{block}{Result}

\end{block}
\end{column}
\pause
\begin{column}{0.48\textwidth}
\textbf{DrugDiscoveryBench} \sm{Akyürek, Tu et al., Scale AI \& Phylo, 2026}
\medskip
\begin{itemize}\footnotesize
  \item 82 \textbf{expert-authored} drug-discovery tasks
  \item Coding agent in a container with a biomedical tool library
  \item Graded by \textbf{LLM judge} against weighted expert rubrics
  \item \textbf{Pass = 100\% of outcome criteria}
\end{itemize}
\medskip
\begin{block}{Result}
Best agent: \rd{51.6\%}\\
And — the useful part — they classified \textbf{226 failing runs} into a taxonomy.
\end{block}
\end{column}
\end{columns}

\pause
\medskip
\centering\textbf{Same architecture as mine. Same tool contract. This is a like-for-like read.}
\end{frame}

\begin{frame}{GeneBench-Pro's diagnosis — read it twice}
\why{This single paragraph is the origin of my entire design.}

\begin{quote}\itshape
``models often complete substantial portions of the workflow but exhibit a consistent gap between
\textbf{noticing} and \textbf{acting} — identifying local diagnostic signals but failing to
propagate the implications to the corresponding analysis decision.'' \sm{(p.\,1)}
\end{quote}

\pause
\begin{quote}\itshape
``In many failures, the agent \textbf{notices} the relevant local diagnostic clue but
\textbf{treats it as a local data-cleaning issue} rather than as evidence that should
\textbf{change the downstream statistical method and QC pipeline}.'' \sm{(p.\,13)}
\end{quote}

\pause
\begin{alertblock}{Unpack that}
The model \textbf{sees} the problem. It runs \code{df.describe()}. It observes the \code{-999}s.
It may even \textbf{print a comment about them}.\\[3pt]
Then it cleans the column and \textbf{proceeds with the analysis it had already decided on}.\\[5pt]
\textbf{The observation never reaches the decision.}
\end{alertblock}
\end{frame}

\begin{frame}{DrugDiscoveryBench's taxonomy — 226 failing runs, classified}
\why{This table is the closest thing either paper gives to a specification for what to build.}

\centering
{\small
\begin{tabular}{@{}lrp{0.50\textwidth}@{}}
\toprule
\textbf{Failure mode} & \textbf{Share} & \textbf{Their definition} \\
\midrule
\rd{Domain reasoning} & \rd{54.0\%} & ``applies an incorrect scientific premise or misinterprets the data it has, \textbf{even though its inputs and tools are correct}'' \\
\addlinespace

\addlinespace

\end{tabular}}

\pause
\medskip
\begin{alertblock}{Read the top row again}
\textbf{Over half of all failures are not coding failures.} The tools worked. The Python was
correct. The model \emph{had} everything it needed.\\[3pt]
\textbf{It just did not let what it saw change what it did.}
\end{alertblock}
\end{frame}

\begin{frame}{Two case studies that determined the design}
\why{Abstract taxonomies are cheap. These two concrete failures are what I actually built against.}

\begin{block}{1. The agent contradicted its own printed output \sm{(DDB, p.\,27)}}
\itshape ``its own code \textbf{printed the correct} group-level count of \textbf{1}, and the final
tally \textbf{used} the atom-level count of \textbf{2} \dots\ It reported 8 interactions instead of 7.''
\medskip\normalfont
\\ \textbf{$\Rightarrow$ A number in the answer that was never in any output. A regex can catch this.}
\end{block}

\pause
\begin{block}{2. The question silently decayed \sm{(DDB, p.\,13)}}
The agent dropped the ``melanoma'' qualifier partway through a ranking task.
\medskip
\itshape ``\textbf{The last chance to catch the slip is at the final answer}: a human who had misread
the task the same way would look at the result, recognise it as a \textbf{meaningless response to
the user's actual goal}, and backtrack. \textbf{None of the failing models caught this.}''
\medskip\normalfont
\\ \textbf{$\Rightarrow$ Nothing was watching the exit. Something must be.}
\end{block}
\end{frame}

\begin{frame}{The finding that says \emph{where to spend the budget}}
\why{DDB re-ran their 6 unsolved tasks, handing the agent the expert's step-by-step playbook.}

\begin{quote}\itshape
``76 out of 82 tasks are solved without any hints in at least one of the trials\dots\ After the
hints, at least 1 of the agents is able to pass \textbf{80 out of 82}. The results suggest that
\textbf{execution is within reach for today's agents should they be given the expert workflow}.''
\end{quote}

\pause
\medskip
Put the two papers together:
\medskip
\begin{itemize}
  \item The models \gd{CAN execute}. Give them the right plan and they finish the job. \sm{DDB: 80/82 with hints}
  \item The models \gd{DO notice}. They run the diagnostics and see the anomaly. \sm{GBP: the gap is in \emph{acting}, not \emph{seeing}}
  \item They fail \rd{in the seam between the two}.
\end{itemize}

\pause
\medskip
\begin{alertblock}{Design thesis}
The bottleneck is \textbf{not} code generation, \textbf{not} knowledge, \textbf{not} context length.
It is \textbf{thread-keeping}.\\[4pt]
So do not spend the engineering budget on making the model smarter. Spend it on making it
\textbf{structurally impossible to drop the thread}.
\end{alertblock}
\end{frame}

\begin{frame}{Part 1 — three things in these papers I do not accept}
\why{A review that is all praise is not a review. (And §7 will show I earned the right to say the third one.)}

{\footnotesize
\begin{tabular}{@{}p{0.40\textwidth}p{0.55\textwidth}@{}}
\toprule
\textbf{The claim} & \textbf{Why I do not buy it} \\
\midrule
\textbf{DDB's failure taxonomy}\newline (the 54\% table you just saw)
& It is built from \textbf{ONE run per (model, task)} — by its own caption. But agent runs are
\emph{enormously} noisy: on \textbf{my} harness the \textbf{same task, same config} gave
\textbf{1/10} on one run of the benchmark and \textbf{6/10} on the next. A single trajectory is not
a description of a model — it is \textbf{one draw from a wide distribution}. \\
\addlinespace
\textbf{``76/82 — execution is within reach''}
& That is not a pass rate. It is \textbf{best-of-N across 12 models $\times$ 6 harnesses $\times$
3 trials}. The best single agent scores \textbf{51.6\%}. And the hint experiment moves
\textbf{four tasks} ($n{=}6$), unrepeated. \emph{I believe the conclusion. This experiment does not
establish it.} \\
\addlinespace
\textbf{``Our judge agrees at $\kappa = 1.0$''}
& Against \textbf{two other LLMs}, on 200 items. $\kappa{=}1.0$ is not reassuring, it is
\textbf{suspicious}: either the rubric is so mechanical the judge is redundant (then grade it
programmatically), or \textbf{three models share a bias} — which is exactly what inter-rater
agreement is meant to catch, and exactly what three LLMs cannot catch about each other. \\
\bottomrule
\end{tabular}}

\pause
\medskip
\centering\wn{My sharpest criticism — that GBP's confidence intervals are broken — needs §7 to land,}\\
\wn{because I have to show you that the same bug happened to me first.}
\end{frame}

\section{4 · The design}
% ===========================================================================

\begin{frame}[shrink=8]{The move: turn the three dropped things into \emph{state}}
\why{Every mechanism below is traceable to a specific, quoted failure. Nothing is here because it seemed nice.}

\centering
{\small
\begin{tabular}{@{}llp{0.42\textwidth}@{}}
\toprule
& \textbf{Mechanism} & \textbf{The documented failure it exists to kill} \\
\midrule
\textbf{Ledger 1} & \textbf{Question Contract}
  & the \emph{question} decays \sm{— DDB \emph{Constraint} 7.5\%; the melanoma case; GBP ``wrong population / wrong scale''} \\
\addlinespace
\textbf{Ledger 2} & \textbf{Findings Ledger}
  & the \emph{finding} is noticed and dropped \sm{— GBP's notice–act gap; DDB \emph{Domain reasoning} 54.0\%} \\
\addlinespace
\textbf{Ledger 3} & \textbf{Evidence Grounding}
  & the \emph{number} reported is not the number printed \sm{— DDB \emph{Derivation} 18.6\% + \emph{Final-answer slip} 3.5\%} \\
\addlinespace
\textbf{Gate 4} & \textbf{Fresh-context verifier}
  & nothing is watching the exit \sm{— ``none of the failing models caught this''} \\
\bottomrule
\end{tabular}}

\pause
\medskip
\begin{alertblock}{The principle behind all four}
\textbf{Make the omission impossible to express, rather than asking nicely for it not to happen.}\\[3pt]
A prompt is a \emph{request} — it competes with everything else in the context and \textbf{loses
ground with every step}. A gate is a \emph{wall}.
\end{alertblock}
\end{frame}

\begin{frame}[shrink=8,fragile]{Ledger 1 — the Question Contract}
\why{Before any analysis, the agent's first action must be to fill this in. It is then re-rendered into context EVERY turn, so it cannot decay.}

\begin{lstlisting}[emph={population,premises,question_is_precise}]
class QuestionContract(BaseModel):
    estimand:    str        # the exact quantity, in one sentence
    population:  str        # WHICH ROWS. the denominator. stated explicitly.
    units:       str        # g? kg? percent? fraction? log-scale?
    constraints: list[str]  # every explicit filter the user stated
    premises:    list[str]  # what the QUESTION assumes - and must be checked
    question_is_precise: bool   # REQUIRED. forces an explicit judgement.
    ambiguities: list[str]  # if not precise: the readings, and which I chose
\end{lstlisting}

\pause
\medskip
\begin{block}{Two of those fields exist because \emph{the evaluation demanded them}, not because I designed them in}
\textbf{\code{premises}} — a question can be \emph{wrong}. \emph{``Which of the four sites had the
highest response rate?''} — there are \textbf{three} sites. Without this field the agent answered
anyway, fluently, and \textbf{laundered a false premise into a fact}. With it: \rd{0/3} $\to$ \gd{3/3}.
\end{block}
\pause
\begin{block}{\code{question\_is\_precise} is a \emph{required boolean}, and that is the entire trick}
The contract already had an \code{ambiguities} list, and the agent left it \textbf{empty every
single time}.\\[3pt]
\alert{A field the model MAY leave empty is a field the model WILL leave empty.}
A required boolean \textbf{cannot be skipped} — and a validator forces \code{ambiguities} non-empty
whenever it is \code{False}.
\end{block}
\end{frame}

\begin{frame}[fragile]{Ledger 2 — the Findings Ledger \sm{(the centrepiece — or so I thought)}}
\why{Attacks GBP's headline finding directly. The mechanism is embarrassingly simple.}

Every time the agent notices \emph{anything} — a sentinel, a wrong dtype, a duplicate, an
imbalance — it must log it:

\begin{lstlisting}[emph={note_finding}]
note_finding(
    observation = "biomarker_x has 47 values of exactly -999.0",
    implication = "missing-data sentinels, not measurements; "
                  "they would drag the mean down by ~30%",
    status      = "open",        # open | acted | dismissed
)
\end{lstlisting}

\pause
\begin{alertblock}{And then the rule that makes it bite}
\centering\Large \code{submit\_answer} is \textbf{hard-blocked} while \emph{any} finding is
\code{open}.
\end{alertblock}

\pause
To close a finding the agent must either
\begin{itemize}
  \item \gd{ACT} on it — pointing at the code step that handled it — or
  \item \textcolor{soft}{\textbf{DISMISS}} it — \textbf{writing an explicit reason} why it does not affect \emph{this} estimand.
\end{itemize}
\textbf{Both are recorded. Both end up in the final report.}
\end{frame}

\begin{frame}{Why that is the notice--act gap, converted into a wall}
\why{GBP: the model ``treats it as a local data cleaning issue''. This design does not let ``local cleanup'' be a terminal state.}

\begin{itemize}
  \item A noticed finding is an \textbf{open obligation}. The obligation must be \textbf{discharged,
        out loud}, before the agent is permitted to finish.\pause
  \item The \code{implication} field is \textbf{where the propagation actually happens} — the agent
        is \emph{forced to write down what this changes}, which is exactly the step the papers
        observe it skipping.\pause
  \item It never says what to \emph{conclude}. On the response-rate task the agent looked at the
        \code{-999} finding and \textbf{correctly dismissed it} — \code{biomarker\_baseline} never
        enters that calculation.
\end{itemize}

\pause
\begin{block}{The distinction that makes this defensible}
We do not force a \textbf{conclusion}. We force the observation to \textbf{reach the decision}.\\
What happens when it arrives is still the model's judgement.
\end{block}

\pause
\medskip
\centering\sm{Cost of the mechanism: about 40 lines and one extra tool.}
\end{frame}

\begin{frame}{The limitation — and what it cost me to learn it}
\why{I wrote this sentence before I had evidence for it. Then I watched it happen.}

\begin{alertblock}{The ledger cannot force the agent to notice something it never looked at}
It converts \textbf{noticed-but-not-acted-upon} into a hard stop. It does \textbf{nothing} about
\textbf{never-noticed}.
\end{alertblock}

\pause
On the Simpson's-paradox task, the agent:
\begin{itemize}
  \item caught the duplicate patients \yes
  \item was \textbf{forced} to act on them, and did so correctly \yes
  \item submitted \rd{$-$0.087}. \no
\end{itemize}
It had \textbf{simply never noticed the confounding} — so there was no obligation to discharge, and
\textbf{the gate had nothing to block}. \emph{The mechanism worked perfectly and the answer was
still wrong-signed.}

\pause
\medskip
\begin{block}{So the ledger is \emph{pre-seeded}}
Anything a deterministic profiler can find — sentinels, duplicate IDs, numeric-looking strings —
is entered as an \textbf{open finding before turn one}.\\[4pt]
Not \emph{printed as a helpful note}. \textbf{Registered as an obligation.}
\end{block}

\pause
\centering\Large\gd{Information can be ignored. An obligation cannot.}
\end{frame}

\begin{frame}{The division of labour the whole design rests on}
\centering
\medskip
{\large
\begin{tabular}{@{}p{0.30\textwidth}p{0.58\textwidth}@{}}
\toprule
\textbf{deterministic code} & finds the \textbf{mechanical} problems, and makes them
\textbf{un-ignorable} \\
\addlinespace
\textbf{the model} & decides what they \textbf{mean} for \emph{this particular question} \\
\bottomrule
\end{tabular}}

\pause
\medskip
\begin{alertblock}{Remember this frame}
It looks like a throwaway. \textbf{§6 will show it is the single most important claim in the
project} — and that I had the two halves weighted \textbf{exactly backwards}.
\end{alertblock}
\end{frame}

\begin{frame}[fragile]{Ledger 3 — Evidence Grounding (no LLM, no negotiation)}
\why{Attacks DDB's Derivation error (18.6\%) and Final-answer slip (3.5\%).}

\begin{block}{The rule, stated in the system prompt as an absolute}
\centering\textbf{Every number you report must have been \emph{printed by code you ran}.}\\
\sm{Estimating is not a permitted operation.}
\end{block}

\pause
\medskip
And it is \textbf{enforced deterministically}, not requested politely:
\begin{enumerate}\footnotesize
  \item regex every number out of the answer's \code{evidence} list;
  \item normalise \sm{(strip commas and \%, compare at 4 significant figures, also test $\times$100 and $\div$100 for the percent-vs-fraction confusion)};
  \item require \textbf{set containment} against the concatenated \code{stdout} of the whole run.
\end{enumerate}

\pause
\begin{lstlisting}[style=plain, basicstyle=\ttfamily\footnotesize\color{bad}]
REJECTED: the values {0.62} in your evidence never appeared in any
executed output. Compute and print them before citing them.
\end{lstlisting}

\pause
\begin{alertblock}{Fifteen lines, and it catches a documented frontier-model failure}
DDB: \emph{``its own code printed the correct group-level count of 1, but the final tally used the
atom-level count of 2.''}\\[3pt]
An LLM reviewer \emph{might} catch that. \textbf{A regex catches it every time, for free.}
\end{alertblock}
\end{frame}

\begin{frame}[shrink=8]{Gate 4 — the exit, and the fresh-context verifier}
\why{``The last chance to catch the slip is at the final answer. None of the failing models caught this.''}

\code{submit\_answer} runs four gates \textbf{in order — cheapest and most deterministic first}.
\textbf{Never pay for an LLM call to catch what a regex would catch.}

\medskip
{\small
\begin{tabular}{@{}rllp{0.36\textwidth}@{}}
\toprule
& \textbf{Gate} & \textbf{Cost} & \textbf{Rejects when} \\
\midrule
1 & Schema \sm{(pydantic)}   & free & malformed \sm{— the \code{ValidationError} text goes back and the model self-repairs} \\
2 & Ledger                  & free & any finding still \code{open} \\
3 & Grounding               & free & a number never appeared in any output \\
4 & \textbf{Verifier}       & \textbf{1 API call} & only reached if 1–3 passed \\
\bottomrule
\end{tabular}}

\pause
\medskip
\begin{block}{The critical design detail: \alert{the verifier does not see the agent's reasoning}}
It sees \textbf{only} the Question Contract, the briefing, \textbf{the executed code and its
outputs}, and the draft answer.\\[3pt]
Show it the chain of thought and it gets \textbf{anchored by the agent's own narrative and
rubber-stamps}. \textbf{A verifier that reads the transcript is a verifier that measures nothing.}
\emph{The fresh context IS the mechanism.}\\[3pt]
It is also a \textbf{different model family} \sm{(agent: Qwen3-30B; verifier: gpt-oss-120b)} — a
model grading its own work is subject to self-preference bias \sm{(Zheng et al., 2023)}.
\end{block}
\end{frame}

\begin{frame}{Why this is \emph{not} a multi-agent system}
\why{The most common thing people build here, and I want to justify not building it.}

\begin{block}{The argument against planner / coder / critic}
The state that matters — the dataframes — \textbf{lives in one kernel namespace}. Every handoff
forces it through \textbf{the lossy channel of natural language} — \emph{which is the exact channel
this entire design works to minimise}.\\[3pt]
Both papers evaluate \textbf{single agents}. DDB gets 51.6\% with one.
\end{block}

\pause
\begin{block}{And note what the verifier already buys me}
The \textbf{only} genuine benefit of a second agent here is \textbf{an un-anchored second opinion}
— and that is purchasable for \textbf{one API call}, with none of the coordination overhead.
\end{block}

\pause
\begin{alertblock}{I would change my mind when\dots}
the task genuinely decomposes into \textbf{independent subproblems with narrow interfaces} —
DDB's own future-work suggestion: route \emph{``structural reasoning, database retrieval, patent
mining, target genetics, and verification''} to different stacks.\\[3pt]
\sm{\textbf{Restraint is only credible if it comes with a trigger.} Same for: no framework, no RAG, no fine-tuning — each has a written condition that would reverse it.}
\end{alertblock}
\end{frame}

\begin{frame}{The unglamorous rails \sm{(table stakes — but they are why it never crashes)}}
\begin{itemize}
  \item \textbf{Step budget (20).} At 3 remaining, every observation is suffixed
        \emph{``(3 steps remaining — converge)''}, so it degrades like an \textbf{anytime
        algorithm} instead of being guillotined mid-thought. On exhaustion it is \textbf{forced} to
        submit with \code{confidence="low"}.\pause
  \item \textbf{Error fingerprinting.} \code{hash(exception\_type, offending\_line)}. Same
        fingerprint \textbf{twice} $\to$ \emph{``state the root cause in one sentence before writing
        more code.''} \textbf{Three} times $\to$ \emph{``choose a different strategy.''}
        \sm{(Reflexion, Shinn et al. 2023, in ten lines.)}\\
        \sm{The two-stage design is deliberate: jumping straight to ``try something else'' makes the
        agent \textbf{abandon a 95\%-correct approach over a typo}.}\pause
  \item \textbf{Duplicate-code short-circuit.} Byte-identical code twice $\to$ return the cached
        observation \textbf{without executing}. Breaks the tightest death loops for free.\pause
  \item \textbf{Kernel preamble.} \code{pd.set\_option('display.max\_rows', 20)} — caps accidental
        dumps \textbf{at the source}.
\end{itemize}
\pause
\medskip
\begin{alertblock}{Honest scoping}
\textbf{This is not a sandbox, and the notebooks say so in a red box.} It is an isolated namespace
in a throwaway venv. Both papers use Docker; \textbf{that is the correct production answer}, and
the \code{run\_python} contract \sm{(code in, stdout out)} is \textbf{deliberately identical} to what
a container-backed executor exposes — so the swap is \textbf{one class, not a redesign}.
\end{alertblock}
\end{frame}

\end{block}

\end{alertblock}

\begin{frame}{Why it lied — and it is not a coding bug}
\why{The hierarchical bootstrap is implemented correctly. It is a bug in what I ASKED it.}

\begin{block}{With 10 runs per cell}
The bootstrap resamples \textbf{with replacement} from \textbf{the ten outcomes I happened to
observe}.\\[5pt]
A cell that came back \rd{1/10} therefore has a bootstrap distribution \textbf{centred near 10\%} —
and it \textbf{cannot reach the 60\% the next run produced}.\\[5pt]
The empirical distribution is \textbf{degenerate near $p{=}0$ and $p{=}1$} — and \textbf{those are
exactly where the hard tasks live.}
\end{block}

\pause
\begin{alertblock}{A bootstrap gives you the sampling variance of \emph{the data you have}}
It knows \textbf{nothing whatever} about the data you did not collect.\\[3pt]
At $n{=}10$, near the extremes, that gap is \textbf{enormous} — and the interval it hands back is
\textbf{too narrow in a way that feels rigorous}.
\end{alertblock}
\end{frame}

\begin{frame}{Why this is the worst bug in the project}
\code{evals/stats.py} opens with a sentence \textbf{I wrote myself}:

directions}, and wrote up \textbf{both} as findings.

result}. \textbf{This is the same error one level up: a confidence interval masquerading as a
result.}

\textbf{An error bar is not automatically an honest number.}\\

\emph{run it again and see if it says the same thing.}

\end{frame}

\end{alertblock}

\begin{frame}[fragile]{The detector, in full: $\sim$20 lines of \code{pd.crosstab}}
\why{The mechanism, stated so you could reimplement it from this slide.}

\begin{enumerate}
  \item For every \textbf{pair of low-cardinality categorical columns}, cross-tabulate.
  \item If one's \textbf{conditional} distribution departs from its \textbf{marginal} by
        \textbf{$\geq$15 points}, the groups \textbf{are not comparable}.
  \item \textbf{Seed it as an \code{open} finding} the agent cannot submit past.
\end{enumerate}

\pause
\begin{block}{It names \textbf{no column, no dataset, no domain}}
It finds \code{arm $\times$ severity} in a clinical trial and \code{channel $\times$ customer\_segment} in an
e-commerce export \textbf{by exactly the same arithmetic}.
\end{block}

\pause
\medskip
\begin{lstlisting}[style=plain]
penguins (clean)   : 0 finding(s)
trial    (medical) : 1 finding(s) -> "arm is imbalanced on severity ..."
sales    (held-out): 1 finding(s) -> "channel is imbalanced on customer_segment ..."
\end{lstlisting}

\medskip
\centering\textbf{Exactly one finding per trap domain — and in both cases \emph{it is the planted
trap}.}\\
\sm{The outcome columns and the sequence artefacts drop out on their own.}
\end{frame}

\begin{frame}{Known limits of this evaluation, stated plainly}
\why{The papers are scrupulous about theirs. Being caught hiding one is worse than having one.}

\begin{itemize}\small
  \item \textbf{The judge is not validated at all.} 5 of 28 tasks are graded by an LLM. DDB
        validated theirs at $\kappa{=}1.0$ against two other judges; \textbf{I read mine's calls and
        they looked right}, which is worth precisely what it sounds like. \textbf{This is the
        weakest link} — and it is why the judge decides five tasks and \textbf{not one more}.
  \item \textbf{The grid cannot separate the ledger from the seeding it feeds.} \code{agent.py}
        seeds \code{if cfg.use\_ledger and cfg.use\_briefing}, so \code{no\_ledger} removes
        \textbf{the gate AND every pre-seeded finding}. \textbf{No config in this grid pulls the two
        apart.} The clean experiment is \textbf{a ninth config, one flag, about a dollar. I have not
        run it.}
  \item \textbf{``4{,}480 runs'' is not 4{,}480 independent trajectories.} The cache key omits the
        config name, so ablations that do not change the prompt \textbf{until a gate fires} replay
        the full agent's cached trajectory. This is \textbf{common-random-numbers pairing} — it makes
        the paired CIs \emph{more} precise, not biased — but \textbf{cross-config \emph{cost}
        comparisons are meaningless}.
  \item \textbf{The central thesis is a bet, not a result.} \emph{``Scaffolding beats model size''}
        is why this runs on a model 14$\times$ cheaper than the best available. \textbf{I never ran
        the big model with no scaffolding, so I have not shown it.} One command, $\sim$\$15.
  \item \textbf{I built the traps, so I know them.} The mitigation is the held-out domain — which
        \textbf{caught me twice}, which is the only evidence I have that the mitigation works.
\end{itemize}
\end{frame}

        the number \code{DESIGN.md} reports and the number this deck uses.
        \sm{\textbf{The script is not automatically right either. A cache deflates a sum.}}
  \item \textbf{Separation table} \sm{(§5)}: computed live from \code{evals/tasks.py}.
  \item \textbf{Detector figures} \sm{(§9)}: \code{evals/results\_confound\_detector.jsonl},
        \code{t4\_simpson} \textbf{8/20 $\to$ 13/20}. \textbf{\code{s4\_simpson\_sales} has not been
        re-run with the detector.}
  \item \textbf{Paper figures} are quoted with page numbers and are \emph{theirs}, not mine.
\end{itemize}
